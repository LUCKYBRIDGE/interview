# 놀토의 내용 고치기

경로는 모두 knoldiscuss 저장소 루트 기준이다.

1. `docs/content-guide.md`(문장, 용어, 통계, 링크 기준)와 `docs/lesson-contract.md`(웹과 AI의 역할)를 읽는다.
2. 고칠 문구를 원본에서 모두 찾는다.
   - `index.html`은 줄이 매우 길다. 통째로 읽지 말고 문구로 검색한다.
   - 같은 문구가 `assets/workroom.mjs`(화면 문자열), `assets/workroom-state.mjs`(글 파일 출력), README, `docs/`에도 있는지 본다.
3. 바꾸기 전에 표를 만든다: 위치, 지금 문구, 바꿀 문구, 이유(용어표, 길이, 낡음, 수업 기준). 표는 작업 기록에 남긴다.
4. 통계와 사실을 고칠 때
   - 출처 페이지를 직접 열어 값, 기준 연도, 기관을 확인한다. 확인한 날짜와 주소를 `docs/audits/`의 내용 점검 문서에 남긴다.
   - 확인하지 못한 값은 그대로 두고 '확인 필요'로 기록한다. 추정 값을 만들지 않는다.
5. 외부 링크
   - 지우지 않는다. 깨진 링크는 대체 주소를 찾고 이유를 남긴다.
   - 더하거나 바꾸면 `npm run baseline:links`로 기준선을 같은 변경에서 고친다. `npm test`가 빠지거나 새로 생긴 링크를 알려 준다.
6. 가상 인물
   - 인물의 말과 설정은 Google 쪽 Gem에 있다. 화면 소개만 바꾸고 Gem 지침과 어긋나지 않는지 본다. 소음 28~32번 지침은 `docs/gems-28-32.md`.
   - 해결책이나 정답을 주는 말투로 소개하지 않는다.
7. 학생 화면과 공개 파일에 실명, 학교·학급, 수업 일시를 넣지 않는다.
8. `npm test`, 바꾼 화면의 브라우저 확인(`discuss-verify`), `PROJECT_STATUS.md` 기록. 사실 확인 결과와 학생 문구는 교사(사용자)가 최종 승인한다.
