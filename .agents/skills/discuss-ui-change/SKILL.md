# 놀토의 화면 바꾸기

경로는 모두 knoldiscuss 저장소 루트 기준이다.

## 시작 전

1. `git status`와 `git fetch`로 남의 변경과 원격 차이를 본다. 내가 만들지 않은 미커밋 변경은 건드리지 않고 사용자에게 알린다.
2. `DESIGN.md`, `docs/plans/ux-revamp.md`의 해당 단계, `docs/architecture.md`의 주소·메시지·저장 키 계약을 읽는다.
3. 바꿀 화면에서 학생이나 교사가 하는 일 하나를 한 문장으로 적고 성공 조건을 정한다. 예: "개인 활동 2단계에서 집중할 문제를 쓴다. 390px 첫 화면에 입력란이 보인다."
4. 지금 화면을 캡처해 둔다(`discuss-verify`의 화면 확인 크기). 폴더는 `.qa/<날짜>-<작업>/`.

## 바꿀 때

- 한 번에 한 화면, 한 흐름만 바꾼다. 동작 변경, 문구 변경, CSS 정리를 한 커밋에 섞지 않는다.
- 같은 곳으로 가는 길을 늘리지 않는다. 버튼을 더하면 없앨 버튼도 정한다.
- 색, 간격, 글자는 `assets/brand.css`의 `--knol-*` 토큰을 쓴다. 새 인라인 `<style>`, 새 `!important`, 다른 파일에서 같은 선택자 재정의를 만들지 않는다.
- 상태를 모두 정한다: 기본, 마우스 올림, 키보드 초점, 누름, 비활성, 빈 상태, 오류, 저장 중과 저장됨, 읽기 전용.
- `alert()`을 새로 쓰지 않는다. 덮어쓰기, 삭제, 모둠원 수 줄이기 전에는 확인을 묻는다.
- 기록 데이터(필드, 저장 키, 파일 형식)를 바꿔야 하면 멈추고 `discuss-records-compat`을 따른다.
- 학생 문구는 `docs/content-guide.md`의 용어표와 문장 기준을 따른다.
- 고친 파일을 부르는 모든 `?v=` 값을 같은 새 값으로 올린다.
- 없앤 기능을 가리키는 문구와 문서(README, `docs/workroom.md`, 화면 안 안내)를 같은 변경에서 고친다.
- 공개 주소(`#personal`, `#group`, 자료 경로 해시, `?explore=1`, `?embed=1`, `?view=both`)는 같은 내용으로 계속 열려야 한다.

## 끝낼 때

`discuss-verify`를 따른다. 화면 변경은 단위 테스트만으로 끝났다고 하지 않는다. 전후 캡처를 비교하고, 확인한 것과 확인하지 못한 것을 `PROJECT_STATUS.md`에 남긴다. 화면 부채 지표가 줄었으면 `npm run baseline:debt`로 기준을 낮춘다.
