- 상태(2026-10-31): 0단계와 1단계를 마치고 배포했다(1단계의 지도안 항목은 결정 5를 기다린다). 다음은 2단계. 정한 결정은 [0002](../decisions/0002-target-devices.md)(주 기기: 갤럭시 탭과 PC, 아이패드도 지원)와 [0003](../decisions/0003-deploy-and-delegated-decisions.md)(단계마다 바로 배포, 결정 3·4는 추천안)에 있다.
- 근거: [기준선 점검](../audits/2026-10-31-baseline.md). 기준: [DESIGN.md](../../DESIGN.md), [내용 기준](../content-guide.md), [수업 기준](../lesson-contract.md). 지킬 계약: [구조와 계약](../architecture.md).

## 목표

1. 학생이 첫 화면에서 지금 할 일을 알고 바로 쓴다.
2. 길이 하나로 보인다: 주제, 자료 또는 기록장, 단계.
3. 아이가 읽을 수 있는 말로 쓰고, 자료의 출처와 시기가 보인다.
4. 기존 기록, 공개 주소, 외부 링크, 소음 주제를 잃지 않는다.

## 단계

### 0단계: 기반 (완료)

저장소를 knoldiscuss로 들여오기, 하네스(AGENTS.md, DESIGN.md, docs, 스킬 6개, Kiro 연결, 검사, CI), 기준선 점검, 이 계획.

### 1단계: 바로 고칠 것 (2026-10-31 완료, 5번 제외)

작은 변경으로 큰 혼란을 줄인다. 기록 형식은 바꾸지 않는다.

1. 소음 주제의 알림창 5곳을 비활성 표시와 짧은 안내로 바꾼다. 탭에도 '준비 중'을 표시한다(결정 4).
2. 화면에 없는 기능, 숨긴 단계, 옛 이름을 가리키는 문구와 STEP 번호, 제작 메모를 고친다(`index.html` 124, 143, 146, 153, 155, 160, 198, 199, 241). README와 `docs/workroom.md`도 함께 고친다.
3. 기록장 도구 상태 줄을 접기 밖으로 꺼내고, 저장 충돌 경고 안에 '기록 파일 내려받기'를 두고, 모둠 최종 확인을 3단계 본문으로 옮긴다.
4. 사이트 QR을 저장소 안 파일(`assets/worksheet/site-qr.png`)로 바꿔 api.qrserver.com 의존을 없앤다. 외부 링크 기준선에서 QR 주소 2개를 이유와 함께 뺀다.
5. 공개 지도안 파일을 결정 5에 따라 처리한다. (결정 5의 답을 기다린다)

완료 조건: `npm test`·`npm run check` 통과, `alert()` 0, 외부 링크 기준선은 QR 2개 외 그대로, 세로·가로 태블릿과 PC 크기 브라우저 확인, 바뀐 문구 목록 기록.

결과: 알림창 5개를 0개로 줄였다. 외부 링크는 QR 생성기 주소 2개만 빠졌다(119개에서 117개). 본문 안 절로 가는 링크(①~④, 조사 자료 다시 보기)가 맨 위로 돌아가던 문제도 함께 고쳤다. 바뀐 문구와 확인 내용은 `PROJECT_STATUS.md`의 2026-10-31 1단계 항목에 있다.

### 2단계: 기록장 단순화

가장 효과가 큰 단계다. 수업에서 쓰는 화면이라 배포 시점을 따로 정한다.

1. 배치 모델을 '기록장 하나와 자료 패널'로 바꾼다. 폭 1024px 이상(가로 태블릿, PC)은 옆 패널로, 그보다 좁은 세로 태블릿은 기록 위에 덮는 시트로 연다. 패널에서는 자료 경로(자료, 인물 인터뷰, 학습 자료, 모둠 도우미)와, 모둠 활동일 때 '내 개인 기록 보기'만 고른다. 왼쪽 편집 iframe, 선택 상자 3개, 빈 상태 2개, 숨은 버튼, 중복된 개인 기록 패널을 없앤다(결정 3).
   - 호환: `?view=both`는 패널 열림으로 읽는다. `interview-explore-pane-v1`의 mode는 both를 열림, writing을 닫힘으로 읽고 route와 y는 그대로 쓴다. knoltalk 화면 키는 읽고 버린다.
2. 첫 화면을 정리한다: 머리글 한 줄, 활동 전환, 단계 표시(`aria-current`), 저장 상태, 첫 입력란. 소개 문구와 안내 상자는 짧게 줄이고 차시 번호는 학생 화면에서 뺀다.
3. 저장·도구·오류 메시지를 상태 줄 하나로 모으고, 기록 파일과 인쇄는 '기록 보관' 메뉴 하나로 묶는다.
4. 공유 카드를 정리한다: ① 이미지 만들기, ② 저장하기, ③ 패들렛에 올리기. 개인은 고른 모둠 패들렛을 앞에 두고 나머지는 접는다. 이미지에 들어갈 글을 버튼 위에 보여 주고, 화면에 없는 이전 근거가 들어가면 알린다.
5. 모둠 2단계 요약을 입력할 때 바로 고치고, 글 파일·인쇄의 단계 번호를 화면과 맞춘다(출력 문구만 바꾼다).
6. 기록장 CSS 다섯 층을 `assets/workroom.css` 하나로 합치고 중단점을 세 구간으로 맞춘다.

완료 조건: 측정 목표의 첫 입력란 위치와 배치 조작 수 달성, 기존 테스트와 새 배치 상태 이관 테스트 통과, 브라우저에서 v1~v4 기록 불러오기·자동 저장·새로고침·다른 창 수정 감지·의견 이미지·인쇄 확인, 중첩 iframe 없음, 키보드만으로 모든 동작.

### 3단계: 자료 페이지 길 찾기

1. 머리글을 한 겹으로 줄이고 탭을 늘 보이게 둔다. 안내 상자, 주제 카드, 활동 버튼의 중복을 정리한다.
2. 홈 패널을 절(위험 찾기, 다른 지역 사례, 숫자로 보기, 더 찾아보기)로 나누고 절 목차를 둔다. 위험 상황 54개는 묶음 8개로 접는다.
3. 숨긴 STEP 2·3·4의 마크업을 정리한다. `openclass-student-inputs-v1`에 저장된 값은 지우지 않고, 값이 있으면 '이전에 적은 내용'으로 보여 준다.
4. `index.html`의 인라인 style과 script를 `assets/`의 파일로 옮긴다. 탭 경로와 인물 데이터처럼 순수한 부분은 테스트를 붙인다.
5. 인물 카드의 나이 표기를 맞추고 인터뷰 버튼을 44px 이상으로 한다.

완료 조건: 자료 경로 7개와 `?explore=1`·`?embed=1` 주소 유지, 기록장 패널의 메시지 계약 유지, 외부 링크 기준선 그대로, 첫 화면에서 인터뷰와 다운로드로 가는 길이 보임.

### 4단계: 내용 정리

3단계와 함께 진행할 수 있다. 사실 확인 결과와 바뀐 문구는 교사(사용자)가 최종 승인한다.

1. 용어표를 화면, 글 파일 출력, 문서에 적용한다.
2. 긴 문장, 어려운 말, 반복된 주의를 정리하고 정해진 문장을 쓴다.
3. 통계 카드 15개에 기관, 기준 연도, 자료 종류, 확인 날짜를 붙인다. 값은 출처에서 확인하고 `docs/audits/`의 내용 점검 문서에 기록한다. 오래된 자료를 표시한다.
4. 해결책을 먼저 주는 문구를 고친다: AI 질문 예시, '모범사례', '시행 중', 시설 개선 수치.
5. Gemini 계정 안내를 붙이고, 다운로드 탭의 교사용 정보를 선생님 자료로 옮긴다.

완료 조건: 바뀐 문구 표(위치, 전, 후, 이유), 통계 15/15 표기, 외부 링크 기준선 유지 또는 사유 기록.

### 5단계: 디자인 마감

선택 상태 모양 한 가지, 간격·반지름·그림자 토큰, 본문 17px·최소 14px, 초점 표시, 움직임 줄이기, 대비, 인쇄를 정리한다.

완료 조건: 측정 목표의 화면 부채 지표 달성, 글자 대비 4.5:1·경계 3:1 확인, 200% 확대 확인.

### 6단계: 문서와 자료 정리

README를 사용 안내 중심으로 다시 쓰고, `docs/workroom.md`를 현재 화면에 맞춘다. 스크립트의 Windows 경로와 의존성 목록을 정리한다. 활동지·지도안 원본 위치를 하나로 정하고(결정 6) discussion 작업 공간의 연결을 정리한다(그 작업 공간을 고칠 때는 따로 승인).

## 진행 방식

- 단계마다 브랜치 하나를 쓰고 그 안에서 작게 커밋한다. main에는 단계를 검증하고 사용자가 승인한 뒤에만 합친다.
- 단계를 시작하기 전과 끝난 뒤 화면을 `.qa/<날짜>-<단계>/`에 캡처해 기준선과 비교한다.
- 배포는 수업이 없는 시간에 하고, 배포 뒤 공개 주소를 확인한다(`discuss-release`).
- 다른 컴퓨터에서 이어 할 때는 먼저 원격을 받고 `PROJECT_STATUS.md`의 최신 항목을 읽는다.

## 열린 결정

답을 받기 전에는 추천 답을 가정으로 쓰지 않는다. 받은 답은 `docs/decisions/`에 남기고 이 표에서 지운다. 번호는 바꾸지 않는다.

정한 것: 1번 주 기기는 갤럭시 탭과 PC, 아이패드도 지원([0002](../decisions/0002-target-devices.md), [0003](../decisions/0003-deploy-and-delegated-decisions.md)). 한 기기를 혼자 쓰는지 모둠이 함께 보는지는 아직 모른다. 2번은 단계마다 바로 배포. 3·4번은 사용자가 맡겨 추천안으로 진행한다([0003](../decisions/0003-deploy-and-delegated-decisions.md)).

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 수업 중에 화면이 바뀌어 학생이 헷갈림 | 수업 없는 때 단계별로 배포하고, 바뀐 점을 교사가 먼저 본다. |
