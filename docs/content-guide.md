# 학생용 내용 기준

학생이 읽는 문구, 가상 인물 소개, 통계·자료 카드, 외부 링크, 다운로드 안내를 쓰거나 고칠 때 따른다. 화면 배치는 [DESIGN.md](../DESIGN.md), 수업 흐름과 AI의 역할은 [수업 기준](lesson-contract.md)을 본다.

- 상태: 개편 기준 초안(2026-10-31). 용어표와 정해진 문장은 개편 내용 정리 단계에서 화면에 적용하며, 그 전에 사용자가 고칠 수 있다.
- 현재 화면에서 찾은 문제 목록은 [기준선 점검](audits/2026-10-31-baseline.md#3-내용)에 있다.

## 1. 문장

- 5학년이 한 번 읽고 할 일을 안다. 한 문장에 한 가지를 쓰고 40자 안팎으로 맞춘다. 60자가 넘으면 나누고, 나열은 목록으로 바꾼다.
- 해요체로 쓴다. 예: "~해요", "~해 보세요". 하지 말라고 할 때는 이유를 함께 쓴다.
- 어려운 말은 쉬운 말로 바꾸고, 꼭 남길 말은 괄호로 풀이한다.
- 같은 안내를 한 화면에 여러 번 쓰지 않는다. 핵심 주의는 2절의 정해진 문장을 한 번 쓰고 다른 곳에서는 짧게 가리킨다.
- 교사용 정보(차시 번호, 수정본 날짜, 제작 메모, 지도안 설명)는 학생 화면에 쓰지 않고 선생님 자료 영역에 둔다.
- 지금 화면에 없는 기능, 숨긴 단계, 옛 이름을 가리키지 않는다. 화면을 바꾸면 그 화면을 가리키는 문구와 문서를 같은 변경에서 고친다.
- 영어 꼬리표(STEP, INTERVIEW 01)와 서비스 이름(Gem, NotebookLM)은 학생 문장에 쓰지 않는다. 필요하면 'AI 인터뷰', '학습 카드'처럼 하는 일로 부른다.

### 쉬운 말로 바꾸기

| 지금 말 | 바꿀 말 |
| --- | --- |
| 발산 | 떠올리기 |
| 검토하다 | 따져 보다, 살펴보다 |
| 재토의하여 보완하세요 | 다시 이야기해서 고쳐요 |
| 명확성과 연결성 | 뜻이 분명한지, 근거가 이어지는지 |
| 공동 의견 | 모둠 의견 |
| 지표, 집계, 공표 | 숫자, 모은 수, 발표 |
| %p | "○만큼 올랐어요"처럼 풀어 쓰기 |
| 적치물, 신변, 미준수 | 쌓아 둔 물건, 몸의 안전, 지키지 않음 |

## 2. 정해진 문장 (초안)

| 쓰임 | 문장 |
| --- | --- |
| 가상 인물 | 가상 인물의 말은 실제 증거가 아니에요. 사실은 자료로 확인해요. |
| 자료 확인 | 자료를 볼 때 누가 만들었는지, 언제 조사했는지, 어느 지역인지 확인해요. |
| AI 도우미 | AI는 의견을 대신 써 주지 않아요. 우리 의견이 분명한지 살펴볼 때만 써요. |

| 저장 | 이 기기의 브라우저에만 저장돼요. 다른 기기에서 이어 쓰려면 기록 파일을 내려받아요. |

## 4. 가상 인물

- 가상 인물은 자기 생활, 감정, 가치를 말하고 학생이 질문할 여지를 남긴다. 해결책, 정답, 정책 목록을 먼저 말하지 않는다.
- 화면의 인물 정보는 `index.html`에 있다. 보행자 안전 24명은 `.walk-card` 마크업, 늦은 시각 소음 32명은 `people` 배열과 `links` 배열이다. 프로필 사진은 `profiles/01.webp`~`profiles/23.webp`이며 소음 인물 1~23번만 쓴다.
- 인물의 말과 설정은 Google 쪽 Gem에 있어서 이 저장소에서 바꿀 수 없다. 화면 소개를 바꿀 때는 Gem 지침과 어긋나지 않는지 확인한다. 소음 28~32번 지침은 [gems-28-32.md](gems-28-32.md)에 있다.
- 실제 학급 학생의 이름과 겹치지 않는지는 교사가 확인한다.

## 5. 통계와 자료 카드

- 숫자 카드마다 무엇의 수치인지, 값, 기준 연도나 기간, 만든 기관, 자료 종류(원자료, 기사, 연구 보고서), 확인한 날짜를 보인다.
- 기사나 연구 보고서를 '원자료'라고 부르지 않는다.
- 기준 연도가 5년 넘게 지난 자료에는 '오래된 자료'라고 표시한다.
- 값을 고칠 때는 출처를 직접 열어 확인하고, 확인한 날짜와 주소를 `docs/audits/`의 점검 문서에 남긴다. 확인하지 못한 값은 그대로 두고 '확인 필요'로 적는다. 추정 값을 만들지 않는다.
- 해결책을 결론처럼 보이게 하는 숫자(예: 시설 개선 뒤 사고 감소율)에는 어떤 곳을 어떻게 비교했는지와 생각할 질문을 붙인다.
- 정책 사례는 '우리 문제에 맞는지 따져 볼 예시'로 소개한다. '모범사례', '시행 중'처럼 결론을 먼저 말하지 않는다. 시행 중인지는 공식 자료로 확인한 뒤에만 쓴다.

## 6. 외부 링크

- 지우지 않는다(소음 주제 포함). 깨진 링크는 대체 주소를 찾고 바꾼 이유를 남긴다.
- 링크를 더하거나 바꾸면 `npm run baseline:links`로 `tests/baselines/external-links.json`을 같은 변경에서 고친다.
- 새 탭으로 열고 ↗를 붙인다. 계정이 필요할 수 있으면 2절의 계정 문장을 근처에 쓴다.
- 검색 결과로 가는 링크는 '검색 결과'라고 쓴다. '자료'나 '사례'라고 부르지 않는다.

## 7. 개인정보

- 학생 실명, 교사 실명, 학교·학급 이름, 수업 일시를 학생 화면과 공개 파일에 넣지 않는다.
- 이미 공개된 지도안 파일의 처리는 [개편 계획](plans/ux-revamp.md#열린-결정)의 결정을 따른다.
