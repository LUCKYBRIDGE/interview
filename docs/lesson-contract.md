# 수업 기준 (웹)

웹이 지켜야 할 수업 흐름과 역할이다. 원래 기준은 형제 작업 공간 discussion의 docs/lesson-contract.md(2026-10-28)이며, 이 문서는 그중 웹에 해당하는 규칙을 옮기고 그 뒤에 사용자가 정한 변경을 반영했다. 두 문서가 다르면 사용자에게 확인하고 양쪽을 같은 때에 맞춘다.

## 1. 차시

| 차시 | 활동 | 다음 활동에 가져갈 기록 |
| --- | --- | --- |
| 1~8 | 기존 토의 학습과 지역사회 주제 선정 | 보행자 안전이라는 공동 주제 |
| 9~10 | 입장 이해, 자료 찾기, 문제 고르기, 아이디어 떠올리기, 개인 의견 정하기 | 개인의 문제, 의견, 이유·근거와 출처 |
| 11~12 | 모둠 의견 나누기, 모으기, 결정하기, 전체 의견 나누기(공개수업) | 모둠의 최종 의견과 근거, 남은 걱정 |
| 13 | 학급 전체 의견 비교·조정, 공동 제안 결정 | 학급의 최종 제안과 결정 이유 |
| 14 | 제안서 작성, 제출 준비, 성찰 | 확인된 내용으로 쓴 제안서와 성찰 |

공개수업 11~12차시 80분은 문제 확인 4분, 나누기 12분, 모으기 24분(기준 확인 4분, 비교·검토 20분), 결정하기 12분, 발표 준비 7분, 전체 공유 16분, 정리 5분이다.

## 2. 기록의 연결

- 개인 활동지는 학생마다 한 장(A4 한 쪽), 모둠 활동지는 모둠마다 한 장(A4 양면 두 쪽)이다. 개인 기록을 보며 설명하고 모둠 기록자는 핵심만 적는다. 같은 내용을 종이와 웹에 다시 옮기게 하지 않는다.
- 가상 인물이나 주변 사람에게 들은 것, 직접 겪거나 본 것, 자료에서 확인한 사실을 구분한다. 가상 인물의 말은 실제 지역 현황의 증거가 아니다.
- 자료의 제목과 출처는 짧게 남기고, 시기와 대상·지역 범위는 읽을 때 확인한다. 이유·근거는 하나라도 구체적으로 연결하되 개수를 채우게 하지 않는다.
- 모둠원마다 고른 문제가 다를 수 있다. 모두의 의견을 들은 뒤 함께 볼 문제를 확인하고, 다루지 못한 의견은 남겨 둔다.
- 모으기에서는 기준(기본: 실천할 수 있는가, 효과가 있는가, 여러 사람에게 도움이 되는가)으로 이야기한다. 기준은 모둠이 고치고 더하고 지울 수 있다. 모든 칸을 같은 분량으로 채우게 하지 않는다.
- 결정하기에서는 최종 의견과 근거, 남은 걱정과 다른 의견을 남긴다. 모둠원 확인은 모두가 같은 생각이라는 뜻이 아니다.

## 3. 웹과 AI의 역할

- 가상 인물은 자신의 생활, 감정, 가치를 이야기하고 학생이 질문할 여지를 남긴다. 문제 정의, 해결책 목록, 주장과 근거를 대신 쓰지 않는다.
- 모둠 결정 뒤 AI 점검은 전달이 구체적이고 분명한지에 한정한다. 발표 자료와 의견 이미지는 학생이 쓴 글의 뜻을 그대로 담고 학생이 확인한다.
- 웹은 인물·자료 연결과 기록 보관을 돕는다. 자동 순위, 승자, 정답을 만들지 않는다.
- 브라우저 저장, 파일 내보내기, 패들렛·Drive 제출(학생이 직접 올림), 기관 제출을 구분해서 알린다. 웹이 대신 제출하거나 동기화하지 않는다.
- 같은 사이트의 자료만 기록장 안 패널에 보여 준다. Gemini와 외부 자료는 새 탭이나 별도 창에서 연다(Gemini는 다른 사이트 안에 넣을 수 없다).
- 기존 소음 주제와 외부 링크를 보존한다. 보존하는 것과 그 정확성·접근 권한을 확인하는 것은 별개다.

## 4. 기록장 기본 구성 (2026-10-31 현재)

| 활동 | 단계 | 기본 입력 |
| --- | --- | --- |
| 개인 | 1 듣고, 찾고, 알고 있던 것 | 자유 기록 한 칸 |
| | 2 집중할 문제 | 한 칸 |
| | 3 아이디어 | 한 칸 |
| | 4 내 의견 정하기 | 내 의견, 이유나 근거 |
| 모둠 | 1 의견 나누기 | 모둠원(3~5명)마다 이름, 제안하는 의견, 장점, 단점 |
| | 2 의견 모으기·장단점 검토하기 | 검토 기준(고치기·더하기·지우기), 함께 비교한 장단점 |
| | 3 의견 결정하기 | 최종 의견, 근거, 남은 걱정 |

추가 문항과 이전 버전에서 쓴 내용은 접기 안에 두고, 내용이 있으면 '저장된 기록 있음'을 표시한다. 이전 내용을 지우거나 다른 뜻의 칸으로 옮기지 않는다.

## 5. 원래 기준과 달라진 점 (확인 필요)

2026-10-28에 사용자 요청으로 바뀐 내용이 discussion의 원래 기준과 다르다. 지금 제품은 바뀐 내용을 따른다. 어느 쪽을 기준으로 삼을지는 [개편 계획의 열린 결정](plans/ux-revamp.md#열린-결정)에 있다.
