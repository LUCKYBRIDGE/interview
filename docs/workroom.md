# 차시별 활동 기록 운영

9~10차시 개인 의견 마련과 11~12차시 모둠 토의는 `workroom.html`에서 각각 기록합니다. 인쇄 활동지는 개인·모둠 각각 한 쪽으로 핵심만 기록합니다. 웹의 상세 항목은 필요할 때 사용하며 모두 채우도록 하지 않습니다. 공통 사고 흐름을 따르며, 기록의 분량보다 서로 다른 입장과 근거의 연결, 의견을 조정한 내용을 중시합니다.

## 개인 기록

기본 화면은 듣고, 찾고, 알고 있던 것·집중할 문제·아이디어·내 의견과 근거의 네 단계입니다. 가상 인터뷰 이름은 새로 적지 않고 조사 자료·기존 사실을 구분합니다. 이전 인물·자료·범위·날짜·별도 근거·미확인점은 '더 기록하기'에 보존합니다.

## 모둠 기록

3~5명으로 조절할 수 있습니다. 각 모둠원 칸의 개인 기록 불러오기는 해당 개인 JSON의 문제·제안·이유·근거·출처를 옮겨 반복 입력을 줄입니다. 교체 확인을 받은 뒤 해당 모둠원의 기존 검토 항목은 비우며, 다른 모둠원과 공동 제안의 글은 보존하고 최종 확인은 모두 해제합니다. 파일 읽기 중 활동이나 기록이 바뀌면 불러오지 않습니다. 잘못된 파일과 취소는 현재 기록을 바꾸지 않습니다. 학생 사회자가 각자 문제·제안·이유·근거를 나누도록 진행합니다. 개인이 다룬 문제가 다를 수 있으므로 함께 비교할 문제를 확인한 뒤 의견을 검토합니다. 실천 가능성, 효과, 여러 사람의 이익을 기본 기준으로 확인하고 필요할 때 보완합니다.

기본 화면은 의견 나누기·모으기·결정하기의 세 단계입니다. 모둠원별 이름·의견·이유와 함께 살펴본 장점·우려 한 칸만 기본으로 기록합니다. 의견별 상세 검토와 보충 항목은 접기 안에 보관합니다. 충분히 검토하고 협의한 뒤 공동 제안, 선택 이유, 핵심 근거, 처음 의견에서 조정한 부분, 남은 걱정과 다른 의견을 남깁니다. 결정 내용을 수정하면 모둠원의 기존 최종 확인 표시가 해제되므로 다시 확인합니다. AI를 활용하는 경우 결정한 설명의 명확성만 점검합니다. 기록 도구는 답을 추천하거나 자동 평가하지 않습니다.

## 보관과 오류 처리

개인과 모둠은 `interview-workroom-v4-personal`, `interview-workroom-v4-group` 키로 분리됩니다. JSON 파일은 UTF-8 2MB 이하로 제한합니다. v1~v3 기록은 모둠 번호 항목을 추가하여 v4로 읽으며, 기존 이름·의견·근거·상세 항목을 보존합니다. 옛 모둠 이름이 ‘3모둠’ 같은 형식이면 번호를 복원합니다. v1·v2 모둠 기록은 토의와 검토 기준도 함께 복원합니다. 이전 저장 키는 지우지 않으며 최신 키가 손상된 경우 옛 기록으로 우회하여 덮어쓰지 않습니다.

저장 실패와 손상 기록을 감지하면 자동 덮어쓰기를 멈춥니다. 다른 창의 저장 변경도 자동 덮어쓰기를 멈추게 합니다. 비활성 활동에 미저장 기록이 있어도 메모리의 내용을 지우지 않고, 그 활동으로 돌아왔을 때 충돌을 안내합니다. 복구 시 현재 내용을 보관하거나, 저장된 기록을 다시 읽거나, 확인 후 현재 내용으로 저장을 재개합니다. 저장된 기록이 읽히지 않을 때 원본 키를 자동 삭제하지 않습니다.

## 검증 범위

`tests/workroom-state.test.mjs`는 불변 업데이트, 기본 기록 독립성, 개인·모둠 분리, JSON 왕복, 잘못된 버전·필드·값·크기 거부, 저장소 읽기·쓰기 실패, 최종 확인 해제, 5명 모둠의 최대 길이 한글 기록 왕복, 개인 기록의 모둠원별 불변 복사와 잘못된 기록 거부, 텍스트 출력의 핵심 내용을 검증합니다. Node 테스트의 모델 커버리지는 실제 브라우저·태블릿·외부 Gemini 권한을 검증한 수치가 아닙니다. 브라우저 입력·저장·재열기·인쇄 및 좁은 화면 QA는 별도 확인이 필요합니다.

작성한 기록 인쇄는 `formatText`의 내용을 별도 요약 영역에 텍스트로 표시하고 입력 양식을 감춰 빈칸 때문에 인쇄 페이지가 늘어나는 일을 줄입니다. 빈 인쇄 활동지는 `materials/`의 PDF를 이용합니다.

## 탐구와 기록 오가기

기록만·탐구만·함께 보기 버튼으로 같은 화면 안에서 전환합니다. 1050px 초과 화면은 탐구와 기록을 좌우로, 작은 화면은 위아래로 표시합니다. 탐구 iframe은 같은 사이트의 index.html만 사용하고 Gemini·외부 조사 링크는 새 탭으로 엽니다. 인물 인터뷰에는 별도 창 열기 버튼도 있습니다. 브라우저가 새 창을 탭으로 처리하거나 팝업을 차단할 수 있습니다.

탐구 패널은 선택한 자료와 스크롤 위치를 sessionStorage의 interview-explore-pane-v1에 기억합니다. 기록과 다른 저장 키이며 창 종료 뒤 복원은 보장하지 않습니다. postMessage는 동일 출처와 해당 iframe/부모를 확인하고 허용된 내부 경로만 받아들입니다. 숨긴 iframe이 scrollY를 0으로 바꾸는 브라우저 동작을 고려해 다시 펼칠 때 위치를 복원합니다. 인쇄에는 탐구 패널을 넣지 않습니다.

2026-10-28에 Gemini 일반 앱과 이 프로젝트의 Gem URL 응답에서 X-Frame-Options: DENY를 확인했습니다. 기존 Gemini Gem 채팅을 이 사이트 iframe에 삽입하지 않습니다. 공식 Gem 공유 안내는 https://support.google.com/gemini/answer/16504957 에 있습니다. Gemini API로 별도의 채팅을 만드는 작업은 기존 Gem 화면 삽입과 다른 범위이며 이번 구현에 포함하지 않았습니다.

## 개인 기록 조회와 이미지 공유

모둠 탭에서 개인 활동 기록 보며 토의하기를 열면 같은 브라우저의 개인 기록이나 개인 JSON 파일을 읽기 전용으로 봅니다. 조회는 모둠 기록을 변경하지 않습니다. 실제 모둠원 칸에 옮길 때는 기존 불러오기와 교체 확인을 사용합니다.

개인 마지막 단계와 모둠 의견 결정하기에서 16:9 이미지 만들기 → 미리보기 → 이미지 파일 저장하기를 사용합니다.1920×1080 PNG에는 의견과 이유·근거 및 보충 근거만 담으며 이름·활동명·조사 과정은 넣지 않습니다. 의견 최소44px·근거 최소36px이며 넘치는 글은 자르지 않고 요약 안내를 표시합니다. 원래 기록은 보존합니다. 직접 공유하는 파일이며 자동 전송되지 않습니다.

## 검토 기준 편집

실천 가능한 방법인가? / 문제 해결에 효과적인가? / 여러 사람에게 도움이 되는가? 를 기본 표시합니다. 수정·삭제·추가 가능하며 최대12개·각200자입니다. 기준 변경 시 최종 확인을 해제합니다. 빈 항목이나 전체 삭제도 저장하며 기본값을 임의로 복원하지 않습니다. 종이 모둠 활동지에도 세 기준과 추가·수정 칸을 둡니다.

## 모둠과 이름 및 이미지 파일명

모둠(1~6)과 이름은 모두 선택 사항입니다. 모둠을 선택하면 파일명은 `3모둠_이름_개인의견-근거.png`, `3모둠_모둠의견-근거.png` 형식이며, 선택하지 않으면 `이름_개인의견-근거.png`, `모둠의견-근거.png`로 저장합니다. 이름도 없으면 `개인의견-근거.png`를 사용합니다. 모둠 미선택 상태에서도 패들렛 제출 링크를 사용할 수 있습니다. 파일명에 쓸 수 없는 문자는 밑줄로 바꿉니다. 이미지 본문에는 의견과 근거만 담습니다.

## 장단점 검토 양식 반영

모둠활동 1단계는 모둠원별 이름·제안하는 의견·장점·단점을 기록합니다. 개인 기록을 불러온 이유·출처는 접힌 참고 영역에 둡니다. 2단계에서는 검토 기준에 따라 장단점을 비교하고, 3단계에서는 넓은 입력란에 최종 의견과 근거를 작성합니다. 이전 changes 필드는 삭제하지 않고 기록이 있는 경우 읽기 전용 참고로 표시합니다. 이미지 생성에 쓰는 proposal·reason·evidence 필드와 JSON v4는 유지합니다.

## 학생용 활동 안내

상단 안내는 개인·모둠 활동에 맞는 순서를 보여 주며 기록할 단계로 이동할 수 있습니다. 단계별 설명과 다음 단계 버튼에는 입력 완료 조건이 없습니다. 의견 이미지에는 의견과 이유·근거만 필요하며, 오류가 있으면 비어 있는 해당 칸에 초점을 옮깁니다. 공유 버튼은 ① 만들기 → ② 저장하기 → ③ 패들렛에 올리기 순서입니다. 패들렛은 이미지 생성 전에도 열 수 있습니다.
